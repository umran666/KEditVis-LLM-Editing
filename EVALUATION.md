## Executive Summary

This audit performs a rigorous, sentence-by-sentence scientific verification of the capstone project abstract against the implemented codebase (`prototype/`), the live Modal A100 GPU backend, and controlled empirical benchmarks on the CounterFact dataset.

The investigation confirms that:
1. **Interactive Prototype & Signal Extraction:** The implementation includes interactive visual analytics, logit-lens vocabulary distributions, snapshot restoration, hidden-state drift visualization, and selected rewrite-tensor Frobenius measurements. Tests establish the checked workflows rather than universal correctness.
2. **Residual Variance Operationalization:** The base paper (*KEditVis*, Chen et al., 2026) relied strictly on cosine similarity between MLP inputs and outputs. The abstract promised "layer-wise residual variance." We successfully bridged this gap by operationalizing and implementing the channel-wise residual variance $\text{Var}_{\text{dim}}(h_l[t])$, residual delta variance, and providing interactive signal switching in both the backend and frontend.
3. **Empirical Reality of Layer Selection:** Seeded random windows had 11.3x higher mean relative selected-tensor change ($\text{Rel-Frob} = 0.1071$ vs. $0.0095$, peaking at $0.6759$) and lower paraphrase scores ($PS = 0.600$), although their likelihood efficacy was highest ($ES = 1.000$). Frozen pre-edit telemetry ($\arg\min \sum |\cos|$) did not establish superiority over the static preset ($[13..17]$ on GPT-2-XL, $p = 0.343$). Tensor-change magnitude alone does not establish catastrophic behavioral damage or its prevention.
4. **Optimization-profile comparison:** Context profiles and the matched standard profile achieved the same aggregate behavioral scores. The incremental effect of per-context fitting and consistency is therefore unresolved. Their higher average selected-tensor change is an observed tradeoff on this pilot, not a general requirement for improved paraphrase success.

**Current-code scope (2026-10-07):** The following tables preserve the original pilot measurements. Their producing build predates the optimizer-step correction and later validation fixes. They have not been regenerated by the current code. Hash snapshots establish file agreement, not successful execution or the source identity of the historical GPU build.

## Detailed Empirical Findings

### 1. Layer Selection Quality (Experiment 1)

Controlled evaluation across CounterFact facts on GPT-2-XL comparing three layer selection policies (window size K = 5):
- **Static Preset ([13..17]):** Upstream recommended default.
- **Telemetry-Guided:** Dynamic frozen pre-edit selection choosing the 5-layer window minimizing the sum of absolute cosine similarity across MLP input/output vectors (argmin sum_l abs(cos(x_in^(l), x_out^(l)))).
- **Seeded Random Baseline:** Uniformly selected 5-layer window seeded by `seed = 42 + case_id`.

#### Analytical Synthesis
1. **Observed selection tradeoffs:** Telemetry windows span `[6..10]` to `[24..28]` in the pilot. Random windows reached relative selected-tensor change 0.6759 and an 11.3x ratio of means versus static selection. These measurements do not establish causal factual localization, catastrophic failure prevention, or behavioral damage from tensor magnitude alone.
2. **No established telemetry superiority:** S = 0.621 versus 0.631 with paired t-test p = 0.343 does not demonstrate superiority or equivalence. Relative selected-tensor change was 0.0097 versus 0.0095. No global optimality or drift-minimization conclusion follows from these ten facts.

### 2. Disentangling Context MEMIT: Budget vs. Algorithm (Experiment 2)

To understand where generalization gains actually originate, we evaluated four distinct optimization profiles on the fixed layer preset [13..17]:
1. `standard`: Pinned upstream GPT-2-XL MEMIT settings (20-step budget, clamp factor 0.75, averaged context key, no added consistency term; [source](https://github.com/kmeng01/memit/blob/80426fd9316cf9a50c5ba15e0912f2c2c5bfe84b/hparams/MEMIT/gpt2-xl.json)). The historical raw records do not include effective hyperparameters or backend source hashes, so their producing configuration cannot be independently reconstructed from those records alone.
2. `standard_budget`: Budget-matched MEMIT (40 Adam steps, clamp factor 1.5, single averaged key, consistency weight 0.0).
3. `context_no_consistency`: Context MEMIT ablation without consistency (40 Adam steps, clamp factor 1.5, multi-key individual context fitting, consistency weight 0.0).
4. `context`: Full Context MEMIT v3 (40 Adam steps, clamp factor 1.5, multi-key fitting, consistency weight 0.01).

#### Key Insights on Algorithm vs. Budget
1. **Matched-profile observations:** The matched standard profile raised likelihood efficacy from 0.800 to 1.000 and paraphrase score from 0.850 to 0.900. The comparison changes both target-fitting budget and clamp settings, so it does not isolate a step-count effect. Case 8 Wellington → Sheffield changed from PS = 0.0 to PS = 0.50 and S = 0.75.
2. **Observed tensor-change tradeoff:** Context profiles had about 77.9% higher mean relative selected-tensor change than standard MEMIT (Rel-Frob = 0.0169 vs. 0.0095, using rounded means). This association does not establish that extra drift is required for better scores.
3. **Consistency attribution remains unresolved:** The consistency term is designed to penalize across-context variation. The saved aggregate behavioral scores do not isolate its benefit. KL values displayed as 0.000 after rounding are nonzero in the raw records, so they do not demonstrate zero collateral change.

> **Provenance caveat.** The "40 steps" profiles in this table were produced by a build whose optimizer loop broke on its final iteration before applying the update, so only **39** gradient steps actually ran. ## Documented Edge Cases and Failure Modes

1. **The Likelihood vs. Greedy Divergence:**
   - On CounterFact evaluation records, likelihood preference rates (ES and PS) frequently register 1.000 because the target token has a higher logit than the original ground truth (P(y_new) > P(y_true)).
   - However, strict greedy exact-match accuracy is far lower: `PS_greedy = 0.550` and `NS_greedy = 0.067`. The model prefers the edited entity over the old entity, but greedy autoregressive decoding may output connecting words or punctuation before reaching the target string.
2. **Paraphrase Vulnerability:**
   - Some evaluated phrasings fail under standard MEMIT. The matched standard profile attained the same aggregate paraphrase score as the context profiles, so multi-context fitting is not established as necessary by this pilot.
3. **Autoregressive Text Generation Repetition:**
   - In unconstrained autoregressive generation, edits applied to non-optimal layer bands can induce repetition loops (e.g. repeated n-grams).
